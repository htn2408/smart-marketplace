# Hoàn thành luồng Filter Task end-to-end

## Mục tiêu
Nối đứt đoạn hiện tại: `TaskDetail` → `POST /api/tasks` (lưu DB + upload ảnh) → `FilterTasker` gọi `POST /api/tasks/filter` hiển thị kết quả matching **thật** từ backend. Không thêm distance score (theo yêu cầu: tasker chỉ đăng ký quận/thành phố, hard filter theo quận đã đủ, các candidate cùng quận nên distance không tạo khác biệt).

## 1. Backend (smart-marketplace-new)

**TaskController.cs**
- Xóa route phụ trùng lặp `/api/filter`.
- Đổi `[AllowAnonymous]` → `[AuthorizeRoles("CLIENT")]` cho endpoint filter (chặn gọi nặc danh).

**dto/FilterTaskersResponse.cs + TaskService.cs**
- Bỏ `Email`, `PhoneNumber` khỏi `CandidateInfoDto` và mapping (chống lộ PII; chỉ trả name, skills, rating, completedTasks, districts).

**TaskRepository.cs — chuyển lọc trùng lịch vào SQL**
- `GetCandidateWorkersAsync` nhận thêm `taskStart`/`taskEnd`, lọc overlap (`otherStart < taskEnd && otherEnd > taskStart`) ngay trong query thay vì load toàn bộ `TasksAccepted` về memory.

**Matching theo mã hành chính**
- Thêm 2 cột nullable `province_code`, `district_code` vào entity `TaskItem`, `CreateTaskRequest` và mapping trong `AppDbContext` (lưu theo code Esgoo).
- `GetCandidateWorkersAsync` ưu tiên so `ProvinceCode`/`DistrictCode` của `worker_districts`; nếu task chưa có code thì fallback so tên như hiện tại.
- Vì dự án không dùng EF migration: tạo script SQL thủ công `smart-marketplace-new/database/alter_tasks_add_codes.sql` (ALTER TABLE + hướng dẫn chạy).

**Kiểm chứng:** `dotnet build`.

## 2. Frontend (sm-fe)

**services/taskService.js**
- Thêm `createTaskApi(taskForm, images)`: dựng `FormData` (title, description, city, district, address, latitude, longitude, scheduledStartTime, expectedTime, offeredPrice, requiredSkillId, images[]) + header `Authorization: Bearer` từ token `localStorage` (`taskmate_jwt_token`).
- `filterTaskersByTaskId` thêm Bearer token (endpoint giờ cần role CLIENT).

**components/common/AddressSelector.jsx**
- Bổ sung `provinceCode`, `districtCode` vào payload `emitChange` (dữ liệu Esgoo đã load sẵn, chỉ cần truyền object đã chọn ra ngoài).

**UsersPages/TaskDetail.jsx**
- Lưu `skillId` khi chọn gợi ý qua `onSelectTask` (đã trả về `item.skillId`); thêm validate bắt buộc phải chọn từ gợi ý để có `requiredSkillId`.
- Lưu thêm `provinceCode`/`districtCode` từ `handleAddressChange`.
- Thay nút "thêm ảnh" đang `alert()` bằng input file thật: tối đa 10 ảnh, chỉ `image/*`, ≤5MB, có preview và xóa ảnh.
- `handleSubmit`: tính `scheduledStartTime` (ISO từ `selectedDate`/`customDate` + `startTime`) và `expectedTime` (phút, từ `startTime`/`endTime`); gọi `createTaskApi`; có state loading/disabled; thành công → navigate `/filter-tasker` với `taskData` chứa `id` thật (dùng làm mã yêu cầu), lỗi → thông báo rõ ràng.

**UsersPages/FilterTasker.jsx**
- Thêm loading state khi đang gọi API.
- API trả 0 kết quả hoặc lỗi → hiện empty state rõ ràng ("Không tìm thấy thợ phù hợp..." + nút thử lại); mock chỉ còn là fallback demo kèm dòng chú thích "Đang hiển thị dữ liệu mẫu".

**Kiểm chứng:** `npm run lint` + `npm run build`.

## 3. Unit test (điểm cộng cho CV)

- Tạo project `smart-marketplace-new.Tests` (xunit), test thuần logic không cần DB: `CalculateRatingScore`, `CalculateExperienceScore` và hàm overlap lịch (trích thành static helper để test được).
- Chạy `dotnet test`.

## 4. Cách demo sau khi làm xong
1. Chạy MySQL + backend (`dotnet run --launch-profile http`), frontend (`npm run dev`).
2. Đăng nhập tài khoản CLIENT → tạo task kèm ảnh ở `/task-detail` → tự động sang `/filter-tasker` thấy danh sách Tasker thật kèm điểm phù hợp từ thuật toán.
3. Thử gọi thẳng `POST /api/tasks/filter` không kèm token → bị chặn 401 (chứng minh đã khóa endpoint).
